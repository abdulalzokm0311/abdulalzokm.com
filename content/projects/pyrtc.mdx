## The problem

pyRTC is an adaptive optics controller. It works, and the people who built it
can drive it fluently. Everyone else meets it as a terminal, a config file and
a set of commands you either know or don't.

A junior researcher joining the lab was spending their first days learning the
tool instead of doing the work. There was no onboarding, because there was no
interface to onboard into.

## Four windows into one

Running the system meant keeping four things open at once: the controller, the
telemetry stream, the config, and the log. Attention moved between them
constantly, and the cost of a mistake was high because nothing was in view at
the same time as anything else.

The dashboard collapses those four into one workspace, with live telemetry, the
current configuration and system state readable without switching context.
